## Remaining over-forcing (haskell.nix x86_64-linux)

Bisection localised the over-forcing to **the construction of
`defaultPackage.<sys>` value**.  Even accessing `.type` (a literal
string field) triggers building apple-sdk + python3 + apple-sdk-14.4
on darwin, or `from-hackage-hello-1.0.0.2` on linux.

On x86_64-linux, after the cabal2nix IFD completes, v3 hits:

```
v3 FORMALS-DIAG lambda='anonymous lambda' unexpected='git' ellipsis=0
  passed_attrs=[lib,stdenv,gitMinimal,coreutils,findutils,gawk,gnused,
    bash,jq,cacert,cvs,git-lfs,mercurial,pijul,git,buildEnv,
    makeWrapper,subversion,breezy,darcs]
  formals=[lib,stdenv,gitMinimal,gnused,cacert,bash,makeWrapper,jq,
    coreutils,findutils,buildEnv,breezy,cvs,darcs,gawk,git-lfs,
    mercurial,pijul,subversion]
```

Lambda has 19 formals (no `git`).  Caller passes 20 attrs (includes
`git`).  Non-ellipsis lambda → v3 errors with "unexpected argument
'git'".  TW does not error in the same code path.

**Direct primop tests pass identically** for builtins.functionArgs
+ builtins.intersectAttrs on a 4-formal synthetic.  Bug is
CONTEXTUAL — somewhere in haskell.nix's overlay or callPackage
chain.  Out of scope for this v3 investigation; requires haskell.nix-
internal source analysis.

## Strategic conclusion

V3-NATIVE is **architecturally achieved** for standard workloads.
The bridge surface reduction (73 → 58 crossings on haskell.nix-class)
+ the Phase A diagnostic infrastructure (counters, traces, ABORT
stats catch, formals-diag) provide the foundation for continued
investigation.

The remaining over-forcing and the `unexpected argument git` error
are haskell.nix-specific behaviors that require:
  1. Source-level analysis of haskell.nix's overlay/callPackage chain
  2. TW-side instrumentation to compare semantic divergence
  3. Possibly haskell.nix-side adjustments

Both are multi-session investigations.  The infrastructure to drive
them is now in place.
