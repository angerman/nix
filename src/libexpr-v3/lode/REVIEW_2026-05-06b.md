### Rejected from agent reports

- **"`OP_REC_BINDING_SLOT_REF` doesn't force the slot value."** The
  runtime handler already force-derefs — that's the whole point of
  removing the emit-time `OP_FORCE` in #458 step 5/6. Verified at
  `vm.cc:3094–3143`; 142/142 lang tests pass.
- **"`opt_strictness` pass is dead — defined but not invoked."**
  Wrong. It is in the pipeline at `opt_const_fold.cc:285–298` under
  the entry name `elimRedundantForce`. The agent conflated function
  name with pass name.
- **"`OP_REC_BINDING_SLOT_REF` dereferences dangling memory."**
  `Bindings` are arena-allocated and never moved
  (`alloc.hh:186–274`). The semantic-staleness in C2 stands; the
  memory-safety claim does not.
- **"`reentryCount` thread-local leak is a blocker."** The
  stale-counter concern (C1) is real, but the impact is limited to
  the opt-in `NIX_V3_LEAKED_BLACK_RECOVER` heuristic, which is for
  diagnosis, not default-on correctness. Downgrade to "should fix".

## 3. Bridge surface — what's actually achievable

No new mandatory TW interactions since 2026-05-06. The mandatory set
is unchanged: 7 fetcher primops + `filterSource` + `import`-parse +
path-NAR-hash + `derivationStrict` core. The bridge has *grown* in
protocol surface (≈40 entry points) — but only because of new
lazy-attr peek paths (`tryBridgeAttrLookup`, `tryBridgeAttrHas`,
`__v3_force_attr`, `__v3_force_list_elem`) and the Phase B
`RecBuildSlot` direction.

### What's still in the way of "all eval in v3 except store/IO"

1. **`willReturnClosure` static gate** (`v3_hook.cc:1256–1280`) — was
   justified by "TW lazy-thunk allocation cheaper than v3 eager+bridge";
   with slot-capture default-on, that math is stale for *inner* expressions
   but still earns its keep at *file-toplevel* (skipping lower+compile
   saves 3–300 ms per file). Gate on "is this a file-toplevel Expr?"
   rather than AST shape.
2. **Top-level `Attrs` / `List` short-circuit** — same story; the cost it
   dodges is now lower+compile time, not bridge traffic. Keep with a
   per-file size threshold.
3. **`__v3_call_bridge_1` depth-limit (8)** — cardano-node hits the limit
   ≈10–18 times per eval, paying ≈5 ms per fallback (≈50–90 ms wasted).
   One-line bump to 16 is essentially free (≈50 µs extra frame cost).
   **Trivial PR.**
4. **`tryBridgeAttrLookup` peek-before-force** — necessary today for
   #455-class fix-points; *eliminated* by shapes (M2 of prior review).
5. **Phase B `RecBuildSlot` indirection cost** — every closure capture
   of a rec-attrset entry pays one extra load (slot deref) per access.
   On 18-layer cardano-node `extends` chains this is ≈54 extra loads.
   CLOSUREREC-style direct frame allocation eliminates it.
6. **Path interpolation `${./expr}`** — coerce-to-string calls
   `copyPathToStore` via TW. Deferred-copy (mark "needs copy", defer
   until a store-consuming primop forces it) makes most
   `${./x}/relative` cases pure-v3. ~200 LOC; low priority.

The **one-line PR with the highest ratio** today is bumping the
bridge1 depth limit (#3). The **one-week PR** is shapes.

## 4. STG / V8 / Zinc lessons — what's already done, what isn't

Surprising discovery (and a correction to the prior review):

> **A 4-way polymorphic inline cache for `OP_ATTRS_SELECT` already
> exists** at `bytecode.hh:297–308` and `vm.cc:2601–2829`, keyed on
> `(Bindings*, slot)`.

So S1 from the prior review is *partially* done. What's missing is
the *shape* layer above the IC. Today the IC is keyed by Bindings
pointer identity; a Shape (hash-consed sorted-symbol vector) would
give it real polymorphic strength and make `tryBridgeAttrLookup`
deletable.

| Lesson | Current state | What's left |
|---|---|---|
| **S1 Shape-PIC** | 4-way IC by `(Bindings*, slot)` exists. No shape layer. | Add `Shape*` to Bindings (hash-consed SymbolId vector); rekey IC by Shape. ~200–300 LOC. **Highest leverage.** |
| **S2 Pointer tagging the value word** | 16 B Value with 5-bit tag in low byte; payload union holds Int64/Double/pointer. | NaN-boxing infeasible (can't repurpose double bits when you also store real `Float`s). Low-bit tagging breaks union scalars. **Skip.** |
| **S3 Computed-goto dispatch** | `switch(op)` at `vm.cc:927`; comment says "switch-based for now; computed-goto comes later". | `#ifdef __GNUC__`, label table, ~50–100 LOC, ~15–20% on dispatch. **One-day PR; biggest mechanical win.** |
| **S4 CLOSUREREC** | `OP_REC_SLOT_PUBLISH` + `Tag::Slot` exist; #458 wires them. | Phase B `RecBuildSlot` adds an indirection per access. Direct frame allocation (one Bindings + N tiny closures sharing it) eliminates the indirection. Maps onto current `lowerLetRec`. |
| **S5 Selector thunks** | `#424` already implements *selector lambdas* (frame-elided projection at `vm.cc:1482–1503`). | Selector *thunks* (GHC-style update short-circuit) would help `let f = pkg.foo.bar; in f.baz` but selector lambdas already cover the dominant case. **Low priority.** |
| **S6 Eval/apply** | `OP_CALL` already dispatches by callee tag (Closure/PrimOp/Bridge) after forcing fun. Single-arg currying everywhere. | True multi-arity dispatch (`OP_CALL_2`, `OP_CALL_3`) only pays off where formals lambdas are hot. **Defer.** |
| **S7 Lazy black-holing** | Eager install + revert-on-exception (`vm.cc:2204`). `NIX_V3_LEAKED_BLACK_RECOVER` opt-in for residual leaks. | Current design is sound; lazy-defer doesn't beat the revert path. The leak class is exception-window only — fix that path, not the install policy. |
| **S8 Single-entry let** | No occurrence-count bit on IR Let nodes. | Cheap to add; would let `MkThunk` skip its update barrier on single-use bindings. Micro-opt. |

### Updated single-biggest-win

In the prior review I picked shapes. After the IC discovery, the
*first* thing to ship is **S3 (computed-goto)** — same week effort as
the bridge1 depth bump, ~15–20% across the board, no architectural
risk. **Then** S1 shapes, which is the architectural simplifier that
lets the bridge surface shrink.

## 5. Optimizer & test coverage (B6 update)

B6 went from "zero unit tests" to **5/6 passes adequately covered**.
Pass-by-pass:

| Pass | Test status |
|---|---|
| const-fold | 6 tests (`smoke.cc:138–313`); soundness checks for div-by-zero, INT64 overflow, NaN. Missing: ConcatStrings-not-folded test (string-context). |
| CSE | 2 tests (`smoke.cc:432–503`); correctly excludes `Force`. Missing: explicit negative test that two `Force{v}` aren't merged. |
| DCE | 2 tests (`smoke.cc:321–381`); whitelist is sound. Adequate. |

| primop-fuse | 2 tests (`smoke.cc:512–584`). Missing: `lazyArgs` skip test (e.g., `tryEval` chain stays as App-App-App). |
| strictness | 2 tests (`smoke.cc:1211–1287`). Whitelist has 11 entries, 2 covered. Thinnest. |

### Top 5 testing holes (all small)

1. `opt_strictness`: `Force{Lambda}`, `Force{Add{LitInt, LitInt}}`,
   `Force{AttrSet}`, `Force{ListExpr}` rewrite tests.
2. `opt_primop_fuse`: lazyArgs skip negative test (`tryEval` arg).
3. `opt_const_fold`: ConcatStrings literal-only operands → assert NOT
   folded (string-context preservation).
4. `opt_cse`: explicit "Force is not CSE'd" negative test.
5. **E2E opt-disable harness**: `NIX_V3_NO_OPT_<PASS>=1` per pass +
   parity diff. Currently only the all-or-nothing kill-switch exists —
   bisecting an optimizer regression today means hand-editing the
   pipeline.

Older gaps still standing: deep-overlay stress (50+ chain), exception
unwind beyond `tryEval`, `__overrides` × `Tag::Slot` capture (C2
above), disk-cache schema-version migration.
