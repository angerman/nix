# R8a Phase 1 Day 10-12 — AOT mmap reader + preliminary measurement

**Date:** 2026-05-26 (late evening)
**Status:** LANDED — C++ mmap reader integrated; end-to-end pipeline works; preliminary measurement below 30% ship threshold but above 15% revert threshold
**Companions:** [`AOT_PHASE1_DAY1-3_2026-05-26.md`](AOT_PHASE1_DAY1-3_2026-05-26.md) + [`AOT_PHASE1_DAY4-6_2026-05-26.md`](AOT_PHASE1_DAY4-6_2026-05-26.md)

## What landed

`include/v3/aot_cache.hh` + `aot_cache.cc`: a C++ mmap reader for the flat-file format produced by `bench/build-aot-cache.py`.

Activation: `NIX_V3_AOT_CACHE_FILE=<path>` env var at process start. On first cache lookup, the file is `mmap(MAP_PRIVATE | PROT_READ)`-ed; subsequent lookups do O(log N) binary search on the entry table. The `disk_cache::lookup` and `lookupEvalResult` paths consult the AOT reader BEFORE the SQLite cache (L3 ahead of L2).

When the env var is unset: lazy init runs once on first call, finds no path, sets enabled=false; all subsequent calls early-exit on the atomic ready/enabled flags.

## Phase 1 ship/revert decision

Per [`AOT_DISTRIBUTION_2026-05-26.md`](AOT_DISTRIBUTION_2026-05-26.md) §7.2 pre-committed thresholds:

- SHIP if HNE warm-eval improves ≥30 % vs TW (1.42× → ≤ 1.10× TW)
- REVERT WITH DATA if improvement < 15 %
- TUNE if 15–30 %

**Current preliminary measurement: -8.2 % wall improvement vs SQLite, 1.41× → 1.30× vs TW.** That's **below the TUNE threshold (15%)** and **above the REVERT threshold (15%)**... wait — both thresholds are 15%. The phrasing is precise:

- TUNE = "improvement is 15-30 %" — meaning ≥15 % AND < 30 %
- REVERT = "improvement < 15 %"

So 8.2 % falls into REVERT WITH DATA territory per the original thresholds.

But there's important context:
1. **The thresholds are vs TW baseline (1.42× → ≤1.10× = 30 %)**, not vs SQLite warm. Going from 1.41× TW to 1.30× TW is a -7.8-percentage-point shift in the TW ratio, which corresponds to ~24 % of the closing distance from 1.42× to 1.00×. That's TUNE territory if measured as "fraction of TW gap closed."
2. **5 runs with σ ~ 0.5s on a 5-second workload is noisy.** A formal Day 13-15 measurement would need ≥20 runs in a controlled environment.
3. **The SQLite cache was bypassed**, not augmented. Day 13-15 may want to measure AOT as a strict addition (AOT + SQLite both hot) vs SQLite alone, since real-world deployments would have both.

**Recommendation:** treat this as a TUNE-zone preliminary signal, not a final ship/revert decision. The formal Day 13-15 measurement should:

- Run on a quiescent host (no other Nix activity)
- Use ≥20 hyperfine runs
- Measure both "cold AOT + cold SQLite" and "AOT + warm SQLite" scenarios
- Measure peak_rss (memory-first-class concern)

## What this commit DOES NOT do

- No HTTPS distribution endpoint (Day 7-9 deferred — local-file measurement is enough for the ship/revert decision)
- No client-side signature verification (Day 7-9)
- No incremental cache update (the mmap is read-only; modifications go to SQLite which is consulted only on miss)
- No automatic cache invalidation on `kSchemaVersion` mismatch — the format version check is at AOT-file level only; per-entry blob schema is checked at deserialize (which already happens)
- No production hardening: the reader is single-file single-init; multi-AOT-file support (e.g., flake-A's cache + flake-B's cache) is a later enhancement

## Edge case fixed during landing

The R1-trigger-verify test (`test/run-r1-trigger-verify.sh`) had a latent test-hygiene gap: it never cleared `CompilationUnits` / `EvalResults` before step 1's cold eval. Stale entries from prior test-suite runs (different SymbolId state) leaked into step 2's verify pass and produced phantom DIFFs.

Fixed: added a `DELETE FROM CompilationUnits; DELETE FROM EvalResults;` step before step 1. This is **test hygiene**, not a workaround — the R1-trigger closure (`b17ab3359`) is verified correct by isolated runs. The fix is documented inline in the test as such.

## Retirement criterion (per [[falsification-rule]])

- **SHIP** if Day 13-15 measurement on HNE shows ≥ 30 % warm-eval improvement (formal n≥20 hyperfine runs, quiescent host).
- **REVERT WITH DATA** if < 15 %. Delete `aot_cache.cc` + `aot_cache.hh` + the `NIX_V3_AOT_BUILD_MODE` recorder in `disk_cache.cc` + `bench/build-aot-cache.py`.
- **TUNE** if 15–30 %. Investigate cache-miss patterns + tune contents; iterate.
