# v3 VM Review — Consolidated Findings (2026-05-05)

## Methodology & confidence

Six review agents ran in parallel over `src/libexpr-v3/`:

- **vm.cc** core interpreter (read end-to-end)
- **v3_hook.cc + bridge_yield.cc + fiber.cc** (read end-to-end)
- **lower / emit / ir / opt_** compiler pipeline (read end-to-end)
- **primops.cc + serialize + disk_cache + value + cli** (deep on serialize/cache/CLI; spot-read on ~30 primops)
- **`.md` report factual audit** (cross-checked load-bearing claims against current code)
- **dead-code + API consistency scan** (header-vs-callers, env-var inventory, opcode emit/dispatch reconciliation)

Findings are de-duplicated, with several per-agent items downgraded where they relied on speculative future code paths or invariants the current code preserves. Each item has a confidence rating.

## 1. Critical (correctness, can land today)

### 1.1 `uint8_t fFlags` truncates `CallFrame::flags` in `OP_RETURN`

- **Location:** `vm.cc:1557, 1563, 1565, 1759`
- **Defect:** `CallFrame::flags` is `uint32_t` (`vm.hh:59`). OP_RETURN reads it as `const uint8_t fFlags = frRef.flags;`. Today both flag bits (`CFF_THUNK_RETURN=0x1`, `CFF_FORCE_RETRY=0x2`) fit in 8 bits, so it's latent. The next flag added above bit 7 silently diverges — and the comments anticipate more flags.
- **Fix:** one-token change (`uint32_t fFlags`).
- **Confidence:** high (latent, not exploitable today, but a trap for the next contributor).

### 1.2 `recBuildCache` keyed by raw `Env*` — ABA-unsafe across GC

- **Location:** `v3_hook.cc:484–511, 2196–2266`
- **Defect:** `thread_local` cache, never invalidated, stores `Bindings*` whose Bridge thunks hold raw `nix::Value*` into `cur->values[i]`. Once the original `Env` is collected, an unrelated future Env may be allocated at the same address and silently match; the cached `Bindings` hands out stale slot pointers.
- **Why this matters:** likely candidate for the cardano-node "#455 silent empty-string" symptom. The hook documentation at `v3_hook.cc:2772–2782` already references that bug.
- **Fix sketch:** clear at evaluation boundary, or key by `(Env*, monotonic Env id)`, or hold the Env via traceable storage.
- **Confidence:** high. This is the most likely real-world correctness bug.

### 1.3 Thread-safety: every v3-hook global is racy under `eval-cores > 1`

The hook layer was written under a single-threaded assumption that the public `eval-cores` setting violates. All of the following are non-atomic increments / unsynchronized container mutations across worker threads:

- `v3SubExprCache` map mutated from many call sites (`v3_hook.cc:478–482`)
- `blacklisted` lambda set — process-global, no mutex (`v3_hook.cc:2698–2705`)
- `v3HookStats` counters (`v3_hook.cc:1141–1145`) — plain `uint64_t` `++`
- `disk_cache::stats()` (`disk_cache.cc:249–253`) — same
- `v3OnDemandRootPopulated` (`v3_hook.cc:104–108`)
- `v3LambdaRoot` map (`v3_hook.cc:124–129`) — written from parser hooks
- `Expr::isV3CacheCandidate` mutated via `const_cast` from concurrent threads (`v3_hook.cc:1003–1004`)

**Decision needed:** either gate the hook to single-threaded eval (assert at startup), or wrap all of the above in a `Sync<>` / use atomics. Bridge-side primop counters in `primops.cc:2382–2384` already use `std::atomic`, so the pattern is established — but it has been applied inconsistently.

- **Confidence:** high; concrete data-race UB.

### 1.4 Disk-cache schema doesn't fingerprint the opcode table

- **Location:** `serialize.cc:24–66`, `serialize.hh:47` (`kSchemaVersion = 2`)
- **Defect:** schema version bumps cover layout changes only. An opcode renumbering or operand-width tweak in `bytecode.hh` between two builds with the same schema version produces silently-mis-executing CUs from disk.
- **Fix:** include either a build-id or a sequence-of-opcode-names hash in the cache magic.
- **Confidence:** high. With the codebase actively churning opcodes, this is a real foot-gun.

### 1.5 Disk-cache key derived from unresolved path

- **Location:** `primops.cc:4595–4644` (`primImport`)
- **Defect:** the SHA-256 input is the literal `path` string handed in, not the resolved `SourcePath`. Symlink retargeting + `dir/default.nix` rewriting both bypass invalidation. Long-running daemons (Hydra, LSP) serve stale CUs.
- **Fix:** key on `sp.resolveSymlinks().readFile()` after `resolveExprPath`.
- **Confidence:** high in long-running processes; nil for the v3-eval CLI.

### 1.6 String-context propagation gaps (real correctness parity break)

Three primops drop runtime-dep context vs. tree-walker:

- **`primSubstring`** (`primops.cc:572–590`) — no `lookupStringContextEntries`/`setStringContextEntries`. Breaks the canonical `builtins.substring 0 0 drv.outPath` idiom for ref-stripping.
- **`primReadFile`** (`primops.cc:2098–2109`) — no context scan, no NUL-rejection, no restricted-path routing.
- **`primToString`** (`primops.cc:436–441`) — context not threaded through list/attrs coercion in `toStringCoerce`. `toString [drvA drvB]` yields `"a b"` with empty context.

These are silent runtime-deps loss and will subtly break derivations downstream of v3 evaluation. **Confidence:** high.

### 1.7 `primPathExists` bypasses restricted-eval / `RestrictedPathError`

- **Location:** `primops.cc:1763–1775`
- **Defect:** uses `std::filesystem::symlink_status` directly. In `pure-eval` / `restricted-eval` modes, v3 can probe outside allowed roots — observable boolean → sandbox escape.
- **Fix:** route through `state.realisePath`.
- **Confidence:** high; security-relevant.

### 1.8 `primSplit` infinite loop on empty-match regex

- **Location:** `primops.cc:1920–1962`
- **Defect:** loop doesn't advance `pos` past zero-length matches. `builtins.split "" "abc"` hangs the evaluator.
- **Fix:** detect `match.length(0) == 0` and `pos += 1`, or reject empty-match regex like tree-walker.
- **Confidence:** high; user-facing crash-shaped behavior.

## 2. High (worth the next chunk of attention)

### 2.1 `tlBridgeFallbackExpr` save/restore not RAII

- **Location:** `v3_hook.cc:1959–1975, 2032–2050, 2451–2528`
- **Defect:** in some throw paths the prior outer Expr's fallback is never restored. A subsequent `primV3ForceAttr` re-entry then routes a cycle-fallback to the wrong Expr, mis-evaluating silently. Phase-E "invert" mode amplifies this.
- **Fix:** RAII guard everywhere `tlBridgeFallbackExpr` is set, like `ScopedEagerBridge`.
- **Confidence:** medium-high; mechanism plausible, repro not constructed.

### 2.2 Fiber-stack values invisible to Boehm GC

- **Location:** `bridge_yield.cc:40–93` + the design comment in `fiber.hh:21–25`
- **Defect:** the design claim that "only mailbox values matter for GC" is wrong once the fiber body holds register copies of v3 `Value`s pointing into the v3 arena while suspended. Currently dormant because `NIX_V3_FIBER_BRIDGE` is opt-in.
- **Decision:** if `FIBER_BRIDGE` is to remain a real future option, register the suspended stack range with `GC_add_roots` on yield. Otherwise consider pruning the fiber path.
- **Confidence:** medium-high.

### 2.3 `primReplaceStrings` defers `tos` typecheck (parity break)

- **Location:** `primops.cc:1099–1148`
- Tree-walker eagerly forces both lists; v3 only forces matched elements. `replaceStrings ["unused"] [42] "hello"` succeeds in v3, errors in tree-walker.
- **Confidence:** high (concrete divergence).

### 2.4 `primMatch` / `primSplit` no regex cache; error-class drift

- **Location:** `primops.cc:1888–1962`
- Hot-path perf cliff (every `lib.versions` call re-parses the regex) and `regex_constants::error_space` is reported as "invalid regex" instead of a memory-limit error.
- **Confidence:** high (perf) / medium (parity).

### 2.5 `primImport` cache never invalidates

- **Location:** `primops.cc:4533, 4557`
- Long-running processes serve old `Value`s forever. Tree-walker uses `mtime`.
- **Confidence:** high in daemons.

### 2.6 `setStringContextEntries` keyed on arena pointer with no reset hook

- **Location:** `alloc.hh:502–520`
- Side table outlives arena resets; pointer reuse silently injects unrelated context onto a fresh string.
- **Confidence:** medium; matters in long-running processes.

### 2.7 `disasm.cc` missing ~15 opcodes + `OP_CALL_PRIMOP` extra-word

- **Location:** `disasm.cc:13–112`
- Not a runtime bug, but every cycle/blackhole investigation that prints disasm gets misaligned output past an `OP_CALL_PRIMOP`. Future debug sessions will be misled.
- **Fix:** complete the `opName` / `opExtraWords` switches; assert unreachable on `default`.
- **Confidence:** high (mechanical, easily verifiable).

### 2.8 `withLookup` swallows `BlackholeError`

- **Location:** `vm.cc:399–417`
- Cycles in `with rec { ... }` report "name not found" instead of "infinite recursion". Diagnoses worse than tree-walker. Re-throw if no enclosing with-scope hits.
- **Confidence:** medium.

### 2.9 `primToPath` doesn't normalize

- **Location:** `primops.cc:1247–1278`
- Accepts `/nix/store/../etc/passwd` and treats it as a path. `CanonPath` is used elsewhere.
- **Confidence:** high.

## 3. Medium (worth fixing, but lower urgency)

- **`OP_FORCE` / `forceValue` Black-set window** (`vm.cc:2024–2090`, `3935–3964`): `valueStack.resize(...)` can throw `bad_alloc` after `t->state = Blackhole` and before frame push; thunk left orphan-Black. Wrap and revert.
- **`runLambda` throwaway VMState leaks Black** (`vm.cc:3695–3711`): no `try`/`catch` around the inner force; if it throws, `clearBlackMarksOnException` is never called for that VMState's frames.
- **`OP_ATTRS_SELECT` IC** (`vm.cc:2531–2538`): IC entry is keyed by `Bindings*` + slot + name; safe today because `Bindings` entries don't move, but the comment doesn't say so. Worth a one-line comment.
- **`primDerivation` omits `.all` attribute** (`primops.cc:4419–4521`): nixpkgs consumers depend on `drv.all`. Build it lazily.
- **`primGenericClosure` accepts float keys via `to_string`** (`primops.cc:1858–1862`): `NaN` collides with `NaN`. Reject like tree-walker.
- **`primFromJSON` duplicate-key behavior diverges** (`primops.cc:5474–5479`): `nlohmann` silently keeps last; tree-walker errors.
- **`ScopedShallowTWAttrsBridge` lifetime overbroad in `v3CallFunctionEntry`** (`v3_hook.cc:2997–3030`): held through bridging the result; correctness fine, but lifetime is wider than necessary.
- **`phaseBFailureCount` is `uint8_t` and wraps** (`v3_hook.cc:401`): saturating-clamp would be safer; default of `kFailLimit=1` per memory note hides this today, but `NIX_V3_PHASEB_FAIL_LIMIT > 1` allows wrap.
- **`Module::recVarIds` / `litBuiltinsVarIds` accumulate dups** (`lower.cc:1288, 554`): use `unordered_set` or `sort+unique`.
- **`primStorePath`, `primOutputOf` lose v3-side context** when bridging through tree-walker (`primops.cc:6004–6098`).
- **`disk_cache::insert` `int`-truncates blob length** (`disk_cache.cc:235`): use `sqlite3_bind_blob64`.
- **`primReadFile` text-mode `ifstream`** does CRLF→LF on Windows (`primops.cc:2098–2109`); CLI `slurp` has the same hazard.

## 4. Findings flagged as speculative or low-confidence

These were raised by individual agents but are theoretical given current emit + dispatch invariants. Document them as "reasoning rests on this invariant" rather than fixing:

- **`OP_RETURN` zeroing upvalues before state-flip** (`vm.cc:1697–1705`): bug only if a thunk re-enters `OP_RETURN` after a partial unwind, which the agent itself acknowledged has no current path.
- **`Thunk` union aliasing across re-suspension** (`vm.cc` `OP_RETURN` ↔ `clearBlackMarksOnException`): relies on the never-currently-reachable Suspended → Black → Evaluated → Suspended sequence. The right fix is the existing TODO at `vm.cc:3970–3979` (mark `Failed`).
- **`vEmptyList`/`vEmptyAttrs` singletons being mutated by hypothetical future ops** (`vm.cc:2105–2310`): no current op does this; flag for future-op authors via a comment.
- **`OP_TAIL_CALL` across closure boundaries with `CFF_THUNK_RETURN`** (`vm.cc:1492–1543`): bodies are pure today; agent acknowledged "no observable corruption."
- **`OP_ASSERT` not forcing its operand** (`lower.cc:1612` / `vm.cc:3174`): only a hazard if the strictness whitelist gets extended to non-bool-typed nodes; not a bug today.
- **`HasAttr` CSE merging across side-effect sites**: agent's own analysis concluded it's safe given current `VarId` uniqueness.

2. **Thread-safety pass** (§1.3): one focused commit converting all hook globals to atomics / `Sync<>`, OR an assertion that `eval-cores == 1` when v3 hook is active. Pick a policy first.

5. **`recBuildCache` Env-identity + `tlBridgeFallbackExpr` RAII** (§1.2, §2.1): plausible root cause of #455.
6. **`primSplit` empty-match guard, `primPathExists` restricted-mode** (§1.8, §1.7).
