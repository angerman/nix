# v3 VM Comprehensive Review — 2026-05-04

Four parallel agents (boundary, primop coverage, bug hunting, architecture)
reviewed `src/libexpr-v3/`. The most consequential claims were spot-verified
(`clearBridgeTables` unused, `addErrorContext` is a stub, fake-blackhole
throw, `recBuildCache` key shape, disk-cache temp-path collision,
`phaseBFailed` blanket blacklist). Findings below are the deduplicated,
critically reviewed superset.

## 1. Headline assessment

The v3 VM is **at parity for direct evaluation** but is structurally still
a **partial owner**: every measured nixpkgs scan crosses the bridge 31–77
times per call hook (per `TRAFFIC-OWNERSHIP-REVIEW.md`), and the boundary
leaks data in both directions. The single dam blocking "v3 owns it all"
is the **closure-out bridge**, which forces ~10 downstream workarounds.
Several of those workarounds are now self-reinforcing (predicate stacks,
blanket per-Expr blacklists, fake-exception routing) and are turning into
latent design debt.

## 2. Five highest-impact findings

### F1. The closure-out bridge is opt-in, and `<formals>` is fenced off entirely
`Tag::Closure → tLambda` is faked as `mkPrimOpApp(__v3_call_bridge_1, h)`
(`primops.cc:2880-2960`), which breaks `autoCallFunction` / `coerceTo*`.
Closures **with formals are refused** by *throwing a synthesised
`"v3 forceValue: infinite recursion (blackhole)"`* (`primops.cc:2950-2952`)
so downstream code falls back via a substring match. This is the most
explicit "papering" pattern in the codebase. Consequence: every nixpkgs
`{config, options, lib, ...}: …` lambda — the dominant shape — re-runs in
the tree-walker. Closing this collapses items #2–#5 in the residual
stack; agents converged on it from three independent angles. (See
architecture-review B2/B3, boundary §3 entries 5–6.)

### F2. Blanket "permanent fail" blacklists hide real bugs
`v3_hook.cc:1996, 2001, 2250, 2254` set `phaseBFailed = true` on **every**
thrown exception, keyed on the AST `Expr*` itself. Symptoms:
- A user-throw inside one upvalue context permanently disables v3
  evaluation for the same Expr in *every other* context.
- Errors are never recovered from (no resurrection on subsequent forces).
- `const_cast` on shared AST is needed (REVIEW MED-12); the AST is
  conceptually shared with tree-walker.

This couples cleanly with **F4** below: the typed `BlackholeError` exists
(`vm.cc:1937, 3896`) but the consumer at `primops.cc:2358-2362,
2549-2554, 2618-2622` discriminates fallback via `strstr(w, "infinite
recursion (blackhole)")` rather than `dynamic_cast`. So a user-supplied
error message containing the blackhole substring silently routes to
fallback; the dam is held by string content.

### F3. `addErrorContext` is a no-op stub
`primops.cc:2208-2229`: implementation drops the prefix message and
returns `args[1]`. nixpkgs's `lib/modules.nix:270` calls this on every
module evaluation (`config = addErrorContext "..." config`). Today this
is a **correctness regression** for v3-evaluated NixOS error reporting —
failures lose their breadcrumb chain entirely. Severity: silent
wrong-output, not a crash. Fix is small (forward to
`EvalState::addTrace` analogue with a deferred wrap).

### F4. Substring-match exception routing is the central anti-pattern
The same `strstr(w, "infinite recursion (blackhole)")` pattern appears
in five places (`primops.cc:2358, 2549, 2618` as `isBlackhole*` lambdas,
plus the synthesised throw at `:2951` and `vm.cc:373/393`). The typed
`BlackholeError` is right there. The fix is mechanical (replace lambdas
with `dynamic_cast`); the design risk is that the substring is now
load-bearing — any unrelated TU emitting the phrase changes routing.
**F1's fake-blackhole throw is downstream of this anti-pattern**, not
orthogonal to it.

### F5. `__`-prefix alias gaps + missing constants cause hot-path bridge tax
v3 registers `__`-aliases for ~64 primops at `primops.cc:6069-6138`, but
the alias batch **omits** `__derivationStrict`, `__import`,
`__derivation`, `__scopedImport`, `__placeholder`, `__currentSystem`,
`__currentTime`, `__nixVersion`, `__storeDir`, `__langVersion`. Every
reference to one of these from a v3-lowered expression hits
`lower.cc:566` "unbound variable" and bridges the **entire surrounding
expression** to tree-walker. Note that in tree-walker, `__currentSystem`
is the *canonical* form — v3 inverted the convention. Fix is a 10-line
registry patch and a `__storeDir` constant primop reading
`nix::settings.nixStore`.

## 4. Architectural blockers to "v3 owns it all" — ranked

| Blocker | Effort | Notes |
|---|---|---|
| **A1. Closure-out bridge for `<formals>`** | weeks | F1. Synthesise a real `tLambda` whose `body` re-enters the v3 dispatcher and whose `env` is materialised from the v3 closure's upvalues. This single change unblocks the call-hook formals refusal at `v3_hook.cc:2077-2099` and the closure-result refusal at `:2199-2214`. |
| **A2. Tag::External round-trip** | weeks | `value.hh:48` declares the tag, but every switch arm collapses to `mkNull`. Used by experimental fetchers / FFI extensions. |
| **A3. Force-hook restricted to closed CUs** | weeks | `v3_hook.cc:1932` skips when `cu->lambdas[0].nUpvalues != 0`. Phase-B coverage is bounded; the env walker can't reconstruct nested rec scopes. |
| **A4. Disk-cache schema needs cross-process invalidation** | days | `serialize.hh:47` hard-gated `kSchemaVersion`; no negative caching; CRIT-1 in REVIEW. |
| **A5. Optimizer runs single-pass, no fixpoint** | days | `opt_const_fold.cc:279-295` — `fusePrimOpApps` enables further folding but the pipeline doesn't iterate. |
| **A6. With-stack snapshot at MAKE_CLOSURE is shallow** | days–weeks | `closure.hh:73-77` `capturedWiths`. Slot pointers can outlive their parent `Bindings*` if not rooted via the chain. |

## 5. The irreducible store-side kernel

Even with A1–A6 closed, these **must** stay tree-walker-routed
(legitimate, not residual): `derivationStrict` (writes .drv to store),
`import` / `scopedImport` (parser + accessor IO), `path` / `fetchurl` /
`fetchTree` / `fetchGit` / `fetchTarball` / `fetchClosure` /
`filterSource` (store / network), `readFile` / `readDir` / `pathExists`
/ `readFileType` (FS via `SourceAccessor`), `toFile` / `placeholder` /
`storePath` / `outputOf` (store-path synthesis), `getEnv` /
`currentSystem` / `currentTime` / `nixPath` / `nixVersion` (process
globals), `__importNative` / `__exec` (dynamic loading / subprocess),
and the `NixStringContextElem` plumbing shared between v3 and TW.
~20 primops, all already follow the "call into store, marshal result
back" pattern.

## 6. Quick-win patch list (≤1 day each, ranked by ROI)

1. **Register missing `__`-aliases + `__storeDir` / `__langVersion`
   constants** — kills F5's hot-path bridge tax with a 10-line registry
   diff at `primops.cc:6138`.
2. **Fix `addErrorContext` (F3)** — restores nixpkgs error breadcrumbs.
3. **Replace `strstr` blackhole detection with
   `dynamic_cast<BlackholeError>`** at `primops.cc:2358, 2549, 2618` —
   closes F4's load-bearing-string surface.
4. **Make disk-cache temp path unique** (`disk_cache.cc:138`) —
   `mkstemp` or pid+tid suffix.
5. **Refactor `phaseBFailed` to be retry-capable or LRU-bounded**
   (`v3_hook.cc:1996…`) — kills the monotonic perf cliff.
6. **Wire `clearBridgeTables()` into the EvalState destructor**
   (`primops.cc:5541`) — closes the daemon-mode leak.
7. **Round-trip `nFunction`/`nExternal` as Bridge thunks**
   (`primops.cc:2962-2974`) — closes the identity-loss bug for
   higher-order code.
8. **Fix `OP_ATTRS_INIT_DYN` header comment** — load-bearing for
   anyone touching the format.

## 7. What to investigate next (cannot conclude from a read alone)

- Cross-thread `currentMailbox` (`bridge_yield.cc:15`) under nested
  `runInFiber` — the inner restore may leave the outer driver's TLS
  unset.
- `arg` lifetime in `v3CallFunctionEntry` (`v3_hook.cc:2155-2160`) —
  Bridge-thunk wrapping of a tree-walker arg slot that may be reused on
  the next call.
- `v3SubExprCache` eviction on `EvalState` destruction — daemon path
  not exercised today.
- `OP_TAIL_CALL` 10⁷ iteration cap on tight nixpkgs folds.
- Whether `opt_inline.cc` ever moves a force across a `with` scope
  boundary, and whether `opt_primop_fuse.cc` reorders the first-thrown
  exception.
