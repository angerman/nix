# R8a Phase 1 Day 1-3 — NIX_V3_AOT_BUILD_MODE manifest

**Date:** 2026-05-26 (late evening)
**Status:** LANDED — manifest infrastructure ready; Day 4-6 (mmap'd flat file format) is the next sub-task
**Triggering context:** [`AOT_DISTRIBUTION_2026-05-26.md`](AOT_DISTRIBUTION_2026-05-26.md) §7.1 + [`DIRECTION_NOTE_2026-05-26.md`](DIRECTION_NOTE_2026-05-26.md) §6 action #5. R1-trigger closure (`b17ab3359`) unblocked AOT distribution at the bytecode level; this is the first concrete Phase 1 step.

## What landed

A new env var `NIX_V3_AOT_BUILD_MODE=<path>` enables a manifest recorder in `disk_cache.cc`. When set, every successful CompilationUnits or EvalResults insert appends one line to `<path>`:

```
<unix_ts> <table> <key_hex> <blob_size_bytes>
```

Default mode (env var unset): no behavior change. Magic-static gate keeps the cost off the hot path.

**268 CompilationUnits inserts, totaling 29.2 MB** on hello.drvPath cold eval. Zero EvalResults — neither drvHashCacheDisk (opt-in via `NIX_V3_DRV_HASH_CACHE_DISK=1`) nor IFD import cache (only triggers on `import` of derivation outputs, not nixpkgs internals) fired for this workload.

## Properties verified

1. **Output parity preserved**: hello.drvPath under `NIX_V3_AOT_BUILD_MODE=...` is byte-identical to TW.
2. **Default mode unchanged**: all-v3-tests core 14/14 PASS without the env var set.
3. **Magic-static cost gate**: env var checked once on first record call, then a constant `FILE*` lookup per insert (negligible).
4. **Atexit cleanup**: manifest closed cleanly on process exit via `std::atexit` registered alongside open.
5. **Manifest header**: format version + column legend in the file itself, so downstream consumers can identify and validate.

## What this enables (Phase 1 Day 4-6 next)

The manifest is the input for Day 4-6 of the Phase 1 spike per AOT_DISTRIBUTION §7.1:
> Day 4-6: build mmap'd flat file from CU disk cache + EvalResults (per EVAL_CACHE §7.1)

The mmap'd flat file format will:
- Concatenate blobs in manifest order
- Build an index at the head: (key, offset, length) per entry
- Be content-addressed by SHA-256 of the entire file
- Be loaded via `mmap(MAP_PRIVATE | MAP_NORESERVE)` for shared-page-cache semantics

Day 7-9 then adds the HTTPS endpoint + signing + client fetch; Day 10-12 client mmap integration; Day 13-15 end-to-end measurement on haskell-nix-example (the Phase 1 measurement gate per AOT_DISTRIBUTION §7.2).

## Pre-committed thresholds (Phase 1 §7.2)

Day 13-15 measurement on haskell-nix-example must show:
- **SHIP if**: warm-eval ratio improves from 1.42× TW to ≤ 1.10× TW (≥ 30% improvement)
- **REVERT WITH DATA if**: improvement < 15%
- **TUNE if**: improvement 15-30%

This commit (Day 1-3) is necessary-but-not-sufficient for the measurement; it provides the data-source enumeration.

## What this DOESN'T do

- Does not build the mmap'd flat file yet (Day 4-6)
- Does not deduplicate manifest entries on re-runs (each invocation appends; consumers must dedup if they care about uniqueness)
- Does not validate that the cache keys in the manifest are still resolvable in the SQLite DB by the time the AOT builder reads them (a cache eviction between insert + build could leave stale keys; future enhancement)
- Does not record cache MISSES or LOOKUPS (only successful inserts — the AOT distribution doesn't need misses)
- Does not capture in-memory caches (drvHashCacheMap, etc. — only their disk-persisted shadows)

## Retirement criterion (codified per [[falsification-rule]])

- **Falsify if**: Phase 1 Day 13-15 measurement shows < 15% warm-eval improvement on haskell-nix-example. Per AOT_DISTRIBUTION §7.2, this triggers REVERT WITH DATA: remove the manifest recorder + the mmap'd file format + the env var; document the limited value; pivot resources elsewhere.
- **Ship if**: ≥ 30% improvement. Manifest becomes permanent infrastructure; promote NIX_V3_AOT_BUILD_MODE from opt-in to "supported documented mode" in USAGE.md.
