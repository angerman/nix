# LEVER-2 — live-representation RSS reduction ("the wall") — 2026-07-04

Post-LEVER-1 execution plan. LEVER-1 (applied-import result cache) SHIPPED
(`e156a9874`, gate passed both axes): eval #2..N of a repeated expression is
free on CPU and adds ~0 RSS. That closes the CPU moat under the user's
repeated-eval workload. The binding remaining constraint is fact #3: **RSS**.

This is a *design/measurement* plan, not a commitment. Per Rule 0 every
workstream below states a pre-committed SHIP/KILL gate and a measurement-first
step-0 falsifier. No workstream builds before its step-0 measures.

## Goal
Reduce v3's *live resident representation* toward TW's, on the single-eval live
set (the daemon steady state = one live eval + LEVER-1's cached result graphs).
The metric is peak RSS on darwin-4, warm, `bench/profile-at-scale.sh` split into
anonymous vs page-cache (per RESULT_STORE_DESIGN §6).

## Non-goals (measured DEAD — do NOT re-propose)
- **Reclaim-based levers**: ImportCache eviction, arena page-release/munmap,
  mid-eval reuse, BiBOP per-type compaction (4 kills), moving evacuation. Gap is
  live representation, not garbage (bibop_campaign, rss_rootcause, beat_tw_v2).
- **Cell-header shrink**: Value 8B (< TW 16B), thunk 24B floor, pair-tax closed.
  "Leaner cells" exhausted (pair_tax_closure, fresh_numbers).
- **Strict-eval / thunk unboxing** as a size lever — measured 1%CPU/0.4%RSS,
  below noise (fresh_numbers THUNK_LEVER_VERDICT).
- **Runtime string/path interning** — falsified ≤25MB HNE (STRINGS_ATTR_SPIKE).
  Re-open ONLY if the result-cache changes the duplication math (WS-E, gated).

## The wall, quantified (M5 cold ~2973MB, authoritative 2026-06-27)
| bucket | MB | % | reclaimable? |
|---|---|---|---|
| arena | 1560 | 52 | live ~592, **~970 dead but UNRECLAIMABLE** (all GC dead) |
| — thunks | 659 | (dominant arena type) | 63% never-forced = real laziness |
| — bindings | 347 | | ≈84–94% of arena *allocations* historically |
| — chars/closures/pairs/lists | ~450 | | |
| elsewhere (malloc) | 1153 | 39 | bytecode/CU/LambdaDescriptor + ImportCache + SQLite + ~360 frag + binary ~310. **ALONE > TW's whole 982MB** |
| boehm | 403 | 13 | FFI floor, reserved-free (fixed, not workload) |

Warm (production) gap @ `e156a9874`: firefox v3 590MB / TW 358MB = **1.65×**;
M5 v3 2245MB / TW 982MB = **2.29×**.

**Honest ceiling up front (see "Program kill" §): even if every workstream below
lands at its optimistic estimate, the summed win does NOT reach TW parity on M5.
The elsewhere-bucket (1153MB, structural VM tax) alone exceeds TW's entire RSS.
Parity would require a different Value representation + no-compile execution
model — a multi-quarter rewrite, out of scope here.** This plan buys the
*addressable* fraction and quantifies the irreducible remainder.

## Step-0 measurements (all before any build; darwin-4, git-noted)
Each is a *falsifier that can kill its workstream before code*:
- **A0**: at a forced major-mark near peak (`NIX_V3_MAJOR_GC_THRESHOLD_MB`),
  count thunks that are (i) live and (ii) statically provably-forced-once by the
  lowerer's existing strictness analysis. Ceiling = those thunks × 24B. The
  63%-never-forced fraction is REAL laziness — untouchable. Only the
  forced-once-but-still-thunked residue is addressable; static strictness
  already shipped and ate most of it (THUNK_LEVER_VERDICT: 3.5% residual).
- **B0**: instrument `LambdaDescriptor` array + CU malloc footprint; split into
  load-bearing vs diagnostic (empty `name`/`contextualName` headers + gated
  counters). #139 estimate: ~38% diagnostic ≈ 75MB M5 / ~25MB ff (25.5MB of the
  ff 42MB CU footprint is the LambdaDescriptor array = 65%).
- **C0**: extend the existing bypass-rate trace (rss_rootcause: 78–93% of allocs
  bypass the 32MB nursery straight to tenured arena). Per-workload: what nursery
  size makes the *live* set fit vs the M5-regressing scavenge-copy cost. There is
  NO universal default (L2_NURSERY_SIZING: firefox −9/−14% CPU at 256MB but M5
  +14–41%). C0 asks: can a per-workload signal pick the size without a GC cycle.
- **D0**: on live Bindings at peak, histogram (i) shape (sorted symbol-id key
  set) duplication and (ii) entry-count. Old data: `alloc@vm.cc:959` = 94.1% of
  arena Bindings allocations from one site; Bindings 347MB live. If shapes
  dedup heavily → shared-shape (hash-consed) header is worth it; if entry-counts
  cluster at ≤2 → small-Bindings inline encoding.
- **E0**: re-run `NIX_V3_STRINGS_ATTR=1` with LEVER-1 cache warm. Only re-opens
  if cached result graphs *increase* string duplication above the 50MB no-lever
  line. Default expectation: stays DEAD.
- **F0**: RESULT_STORE_DESIGN §1 falsifier (already written): `T_hit_eager /
  T_eval` and `materialised_arena_bytes / blob_bytes`. F is about the *cache's*
  RSS (v2 lazy mmap = working-set not graph-size), orthogonal to base live set.

## Pre-committed gates (write BEFORE measuring — binding)
Threshold basis: below-noise on darwin-4 ≈ 20MB / ~1%; a lever must clear it or
it's a KILL. RSS gates are peak, warm, N=5 median, `--brute` byte-id required.
- **WS-A** SHIP: ≥ 40MB M5 peak-RSS reduction, byte-id, no CPU regression >2%.
  KILL: < 20MB (below noise) OR any byte-divergence. *(A0 likely KILLs it — the
  addressable residue is ~3.5% of thunks; documented pre-kill expectation.)*
- **WS-B** SHIP: ≥ 40MB M5 (side-table strips diagnostic bloat off the hot
  array; lazy-load descriptors). KILL: < 20MB OR breaks error-message UX / IR
  tooling. *Lowest-risk, cleanest residual — likely the first real ship.*
- **WS-C** SHIP: ≥ 60MB M5 peak-RSS AND M5 CPU regression ≤ 5% (the nursery
  tradeoff bar). KILL: any M5 CPU regression > 10% (the L2 curve's danger) OR <
  30MB. High risk: touches the always-on moving-GC nursery.
- **WS-D** SHIP: ≥ 80MB M5 (Bindings is 347MB live; shared-shape or inline-small
  must clear a real fraction). KILL: < 40MB OR byte-divergence OR CPU > 5%.
  Highest correctness risk (Bindings is the drv-hash-critical path — #696 class).
- **WS-E** SHIP: never (expected). Re-run only; KILL on the standing < 50MB line.
- **WS-F** = RESULT_STORE_DESIGN gates verbatim (§1 hit ≤0.20× re-eval; §6 v2
  anonymous RSS ≤ cold baseline). Its own doc owns the phasing.

## Kill criteria (per-WS, explicit)
A workstream dies when its step-0 falls below the KILL line, when a byte-id
regression appears the `--brute` battery catches, or when the build's measured
win regresses from the step-0 projection (the BiBOP lesson: perfect-compaction
projections were falsified by implementation — WS-C/D carry the same risk and
must re-measure post-build, not trust the projection).

## Sequencing
1. **B first** — lowest risk, cleanest residual, no GC/correctness exposure,
   attacks the under-weighted `elsewhere` bucket that the whole campaign ignored
   while chasing arena. Step-0 B0 is a pure instrument.
2. **A0 + D0 + C0 in parallel as measurements** (no code) — they share the
   peak-live major-GC harness (`NIX_V3_MAJOR_GC_THRESHOLD_MB`). Report ceilings.
3. Build **D** if D0 shows shape/size duplication clears 80MB (the biggest live
   arena bucket). Build **C** only if C0 finds a cheap M5-safe nursery signal.
   A is documented-KILL-expected; run A0 to confirm, then close.
4. **F** proceeds on its own doc's schedule (independent of A–D; it's the cache's
   RSS, which grows as LEVER-1 gets used more). F is the lever that keeps
   LEVER-1's win from *adding* to the wall.
5. **E** re-run once, expected close.

## What would make us STOP (overall program kill)
The honest ceiling: optimistic sum of A+B+C+D ≈ 30+75+60+100 = **~265MB on M5**,
taking v3 2245 → ~1980MB warm, still **~2.0× TW**. The `elsewhere` structural VM
tax (1153MB: bytecode + CU + caches + malloc frag) and the live-arena floor
(~592MB) together already exceed TW's 982MB. **No combination of these levers
reaches parity.** Therefore:

- **STOP the RSS-lever hunt** and declare "1.6–2.0× TW resident is v3's
  structural floor under the current Value/VM representation" **if** B ships,
  A0/C0/D0 all measure below their SHIP lines, and F's v2 ships (cache RSS
  bounded). At that point RSS parity is not a lever question but a
  representation-rewrite question (TW-style 16B niche-tagged Value inlining
  int/bool/null/small-list at zero extra bytes + a no-compile execution model) —
  a multi-quarter program to be decided separately, NOT more single levers.
- The value delivered by this plan is then: the addressable RSS fraction banked
  (B + whichever of C/D clears its gate) + a *quantified, defended* floor + F
  ensuring LEVER-1 doesn't regress RSS. A clean "this is the floor" verdict with
  the measurement to back it is a successful deliverable (mirrors the BiBOP KILL
  and env-capture KILL — a defended negative is a result).
