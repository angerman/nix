# v3 VM Review — Consolidated Findings (2026-05-06)

Multi-agent audit of `src/libexpr-v3/` focused on:
1. Pure-v3 vs tree-walker (TW) work, with the goal of "everything in v3 except
   genuine store/IO interaction".
2. Bugs, defects, incomplete work — critically reviewed (several agent-flagged
   "blockers" rejected on inspection).
3. Simplification opportunities, integrating lessons from STG / Zinc /
   G-machine / TIM / V8 shape-PIC literature.

## Methodology & confidence

Six review agents ran in parallel:

- **bridge boundaries** — every place v3 calls back into TW, classified
  mandatory vs avoidable vs perf-policing
- **lowering / IR / VM coverage** — what AST shapes the lowerer cannot handle
  natively; opcode / opt-pass completeness
- **primop coverage** — native vs bridged vs missing, vs the canonical TW set
- **VM design literature survey** — STG, G-machine, TIM, ABC, Zinc, V8 PIC,
  selector thunks, lazy black-holing, eval/apply, TCO in lazy languages
- **bug & defect scan** — FIXMEs, suspect patterns, exception-safety, GC and
  re-entrancy hazards
- **test-suite holdouts** — runner inventory, coverage gaps, the 6 documented
  intentional divergences

Each agent's report was reviewed against the actual code. Items below carry a
confidence tag: **C** (verified), **L** (likely; cited but not personally
checked), **S** (speculative — flag, don't act on without verification).

### 1.2 Bridges that are **not** about the store (real targets)

These are the bridges that stand between v3 and the stated goal of "TW only
for store/IO":

| Site | What | Why | Class |
|---|---|---|---|
| `willReturnClosure` static gate | `v3_hook.cc:1172` | result is `Tag::Closure`; no marshalling shim | architectural |
| Lambda-result refusal at runtime | `v3_hook.cc:1955` | same | architectural |
| Top-level `Attrs` / `List` short-circuit | `v3_hook.cc:1649` | TW lazy-thunk allocation cheaper than v3 eager + recursive bridge | perf workaround |
| `__v3_call_bridge_1` (closure call-back) | v3_hook + vm | TW's `callFunction` → v3 via primop | bridge plumbing |
| `__v3_force_attr` / `__v3_force_list_elem` | vm | TW-side lazy-bridge thunks | bridge plumbing |
| `OP_FORCE` against `Tag::Bridge` | `vm.cc:2026` | every TW-wrapped value forced | inner loop |
| `tryBridgeAttrLookup` peek-before-force | `vm.cc:428, 2476` | partial-bindings access on TW attrset | inner loop |
| `derivation` outer wrapper | `primops.cc:7076` | only the `derivationStrict` core needs the store | port-able |

Three buckets: (i) the `Tag::Closure` architectural gap, (ii) per-call/per-attr
inner-loop bridges that only exist because some Value lives on the TW side,
(iii) static short-circuits in the hook that are pure perf-policing.

### 1.3 Lowering gaps preventing pure-v3 evaluation

- **Path interpolation `${./file}`** — only static path is lowered;
  interpolation falls back. (C, Agent: lowering)
- **Mutually-circular formal defaults `{a ? b, b ? a}: ...`** — sibling slots
  read eagerly; documented limitation (USAGE.md:292), **no test**. (C, Agent:
  lowering + tests)
- **`with` on direct value-stack slots** — only rec-attrset slot-aliasing
  supported; lambda-param slots dangle. (`lower.cc:1683–1686`, C)
- **#425 formals-rec level tracking** — deferred; nested `let`/`with` inside
  formals body shifts level numbers, hits Phase-B noUpv events.
  (`lower.cc:740–751`, C)
- **#457/#458 Lambda-in-let-rec collision** — `subExprFuncs.emplace`
  first-wins picks the THUNK fid for Lambda Exprs; Phase E lift currently
  masks via closure-result refusal. (`lower.cc:1317–1354`, C)

## 4. Simplification opportunities from the literature

The VM-design survey (STG, G-machine, TIM, ABC, Zinc, V8 PIC) maps onto
specific simplification + perf wins. Ordered by leverage for *this* VM's
shape:

### S1. Shape-PIC for attrsets — single biggest win

Every `Attrset` carries a `Shape*` (hash-consed sorted-symbol vector). Every
`OP_ATTRS_SELECT` site has an inline cache `(Shape*, slot_offset)`. Hit path
is `if (set->shape == cache.shape) return set->slots[cache.offset]`;
polymorphic up to ~4 shapes; megamorphic falls back to today's lookup.

This is **simplification, not just perf**:

- Directly addresses the `prev // overlay final prev` env-shape pathology
  (#455). `//` becomes a *cacheable shape transition* rather than a lookup
  explosion.
- Composes with selector thunks (S5).
- Lets the `tryBridgeAttrLookup` peek paths collapse — a TW-side attrset
  with a known shape is queryable across the bridge without a force.
- ~1 word per attrset + a global hash-cons table + 16 B per cache slot. ~800
  LOC, additive, no GC / dispatch / bridge protocol changes.

References: Hölzle/Chambers/Ungar *PIC* (ECOOP 1991); V8 hidden-classes.

### S2. Pointer-tag the value word (STG dynamic tagging)

Spend 2–3 low bits of the pointer half as `EVAL | THUNK | ATTRSET |
PRIMOP_PAP`. `forceValue` becomes one mask + branch — no header load. ~10–15 %
on lazy code in GHC; touches every value-producing opcode + `forceValue`.
Reference: Marlow, *Faster laziness using dynamic pointer tagging* (ICFP
2007).

### S3. Computed-goto dispatch

`#ifdef __GNUC__`, replace `switch(op)` with threaded `goto *labels[op]`.
15–25 % on dispatch-bound workloads; one-time mechanical change.
Reference: Leroy, *Zinc* (INRIA RT-117, 1990); OCaml `runtime/interp.c`.

### S4. CLOSUREREC-style recursive bindings

Allocate one frame block, N tiny closures sharing it — instead of N thunks
with patched pointers. Maps onto the env-carrier path in `lowerLetRec`;
replaces much of the WC-38 slot-aliasing bookkeeping
(`lower.cc:1671–1707`). Reference: Leroy, Zinc; OCaml `byterun/interp.c`
`CLOSUREREC`.

### S5. Selector-thunk short-circuit (GHC)

When an `attrs.foo` thunk's parent attrset updates, all pending selector
thunks short-circuit to the slot value, breaking indirection chains.
Nixpkgs is dominated by `pkgs.haskell.compiler.ghc98.…` chains; this
collapses them on first force. Pairs with shapes (S1) for IC-able offsets.
Reference: GHC `rts/sm/Evac.c` `eval_thunk_selector`.

### S6. Eval/apply at the call site

Marlow & Peyton Jones, *Making a fast curry* (ICFP 2004). Statically known
callees emit `OP_CALL_<arity>`; unknown calls go through generic `apply_n`.
Verify the current OP_CALL already looks like this and tighten where it
doesn't.

### S7. Lazy black-holing

Nix is single-threaded for evaluation. Blackholes exist only to detect
`<<infinite recursion>>`. Defer the install until re-entry is suspected
(walk the eval-stack on suspected re-entry). This is the *root*
simplification of the WC-37 family — fewer marks installed → fewer to clear
→ no ghost-frame corruption to fix.

### S8. Single-entry let

`let x = e in body` where `x` occurs syntactically once and not under a
lambda → skip the update barrier. Already classified at lowering time; an
extra IR bit unlocks it.

## 5. Architectural recommendations

Three concrete moves in order:

### M1. Finish the v3-primary inversion (closes the closure-bridge gap)

(See `project_v3_primary_inversion` memory.) When an Expr's result is
`Tag::Closure`, *return it* instead of refusing; route TW's later
`callFunction` through `__v3_call_bridge_1`. Phase E is already default-on.
Lift the remaining static short-circuits (`willReturnClosure`, top-level
`Attrs`/`List`) one at a time with bench gates. Deletes ~500 lines of
`v3_hook.cc` decision logic.

### M2. Adopt shapes (S1) before adding more lowering features

#425 / #457 / #458 are all *symptoms* of "attrset+env identity is unstable
across rec / with / formals." A `Shape` makes the identity first-class and
turns those bugs from "subtle invariants in `lower.cc`" into "shape
transitions you can write down." Do this before more emit-time invariants
accrete.

### M3. Fold the bridge-thunk peek paths

Once shapes exist, `tryBridgeAttrLookup` and friends collapse: a TW-side
attrset with a known shape is queryable without a force. The
`__v3_force_attr` / `__v3_force_list_elem` primops shrink to the cases where
TW genuinely owns the data (store-derived attrsets).
